# 交叉评审：让结构来自“谁把画面带给谁”

2026-11-03。已阅读 [大厂体验研究](big-tech.md)、[人类专家研究](human-experts.md)、[前端技能研究](frontend-skills.md)、Anthropic 原版 [frontend-design SKILL.md](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)，并查看 [当前正式语音界面截图](baseline-voice.jpg)。以下是设计评审和待验证提案，不是多人实测结论。

## 先修正事实范围

[human-experts.md](human-experts.md) 文首称“Windows 房主运行单 EXE，其他人通过浏览器加入”，容易让人误认为只有房主运行程序。当前产品要求**每位参与者在自己的 Windows 电脑上运行同版本单 EXE，再通过各自浏览器加入**。房主负责维持房间；任一成员可以轮流分享。本评审不直接改动该研究文件。

## 研究是否真的导出了新结构？

两份研究都正确地把状态可信、权限由浏览器决定、退出可恢复和陪伴感从“视觉美观”中单独提出。它们的启发适合形成验收标准，但从原则到界面结构还差一次具体推导：**哪个真实对象保持身份，哪些空间随谁的行动改变，别人看到什么，失败时哪里不变**。若只给原有布局改名、换材质或增加入场动画，并不能证明产生了新的体验。

- **生长的票**：如果只有房间卡变大再显示头像，就是 Portal 的过渡版本。只有在“正在加入/加入失败”保持原票身份、其他房间刷新不夺焦点、进入后真实房间仍承载此前上下文，并且非动画模式也讲得通时，才是有价值的连续交互；这个条件仍不足以保证它视觉上有新的识别度。
- **声音台**：如果只是将三张头像卡排列得更像调音台，就是 Orbit 换皮。必须围绕真实音频来源与本机收听关系重排，并诚实说明音量只影响自己；不能用没有信号来源的声波或闪烁来制造陪伴。要证明它好，用户应在安静、不说话时仍知道谁在，以及哪个声音会被调节。
- **接力轨道**：如果只是画出“等待→分享→结束”三个阶段并贴在播放器上，就是流程装饰。只有它随已确认共享席位变化呈现当前可执行动作、失败后回到可重试状态，才能改变交接理解；目前不存在排队、请求或自动交棒协议，轨道不得暗示这些能力。再者，永远让一次看视频的人阅读时间线可能增加负担。
- 人类专家研究的共同旅程、共同舞台和接力台，分别提出时间、空间与交接轴；它们是有用的概念维度，但当前描述仍允许相同的“画面 + 三头像 + 按钮”落地。应比较真实状态下的结构变化和操作位置，而不是名称或首屏配色。

## 从实际基线看，什么显得像默认生成界面

截图是影院主题、一个房主和两个空位的语音房间：顶部有全局状态与退出，中段“房间”标题和“一起聊，随时分享”口号，下方一个大面板内含三张同尺度座位卡，下面另是一整条操作卡、手动加入卡和两个设置卡。它清楚地暴露空位及主要动作，这是现有优点；但空位占据与本人相同的大块面积，重要的“朋友尚未加入”和空的画面席位没有形成独特关系，观者需要在头像卡和操作带之间拼接当前活动。截图只能证明这个视口和状态，不足以断言其他分辨率、主题或真实媒体表现。

同项目的暖白主题使用奶油底与陶土强调色；当前截图为深色影院，不能说截图本身是奶油主题。真实 [frontend-design 技能](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md) 将奶油/陶土组合和等权圆角卡片列为常见生成式默认，强调它们并非禁用，而应由题材与具体任务证明必要。这里更值得怀疑的是：**两张空位为何有与真实成员同等分量，一串卡片为何能表达三人如何轮流共享**。仅将奶油改成蓝色、把卡片改成票、或加一句“朋友在一起”，仍无法回答。大胆之处应集中在一个与真实共享关系绑定的结构，其余文字与控件保持克制、熟悉、可读。

## 新方案：「来源展开」——三条人名边，谁分享谁让出画面

**结构命题。** 房间不是一张会生长的票、一个围坐头像圈，也不是一条事件时间线。它有一个持续存在的“共享面”，旁边是最多三条窄而清晰的**成员边**：每条边是一名真实在场成员的名字、房主/本机标记和由应用确知的状态。空位用一行“还可加入 N 人”表达，不绘制两张等权空卡。无人共享时共享面不伪造黑播放器，而显示“现在在房间里”和一个清楚的“分享我的屏幕”；成员边与共享面始终属于同一会话。

**唯一大胆表达。** 当某个成员的真实共享状态到达，该成员边变成共享面的来源标记，与画面相接；其他成员边压缩并保留在同一侧。空闲时这一标记退回成员列表。变化由真实成员 ID 与 presenter 状态驱动：它在视觉上说“这块画面来自这个人”，不使用动态声波、头像假亮灯、推测注意力或社交情绪。页面的其余部分保持平静的高对比、清楚中文与常规按钮；可用非奶油配色，但配色本身不是方案的创新。

宽屏示意（位置可调整，文字为状态示例，非定稿）：

```text
房间名      2 人在房间                            离开房间
┌ 成员边 ─────┬──────────────────────────────────┐
│ 我 · 房主   │                                  │
│             │  现在在房间里                    │
│ 林 · 成员   │  分享画面或先和朋友聊            │
│             │                                  │
│ 还可加入 1 人│  [分享我的屏幕]                  │
└─────────────┴──────────────────────────────────┘
  [开启麦克风]  [声音]  [手动邀请]             [设置]

林开始共享后（实际状态确认）：
┌ 林 · 正在分享 ┬────────────────────────────────┐
│ 我 · 房主      │                                │
│                │     完整共享画面 / contain    │
│                │                                │
└────────────────┴────────────────────────────────┘
  [开启麦克风] [只聊语音] [声音]       [全屏观看]
```

**区别与反证。** 相比 Portal，视觉身份不是入场卡放大，而是实际分享者与来源关系；相比 Orbit，人物不是中心环绕陈列，而是会依据真实共享权改变主次；相比 Edge，操作收纳不是核心，画面来源与旁人关系是核心；相比接力轨道，没有虚构未来事件或进度。若移除来源与画面的连接后截图和操作完全不变，这个结构就只是换词，应放弃或重做。

## 五个时刻与实现边界

| 时刻 | 用户看到和能做的事 | 实现约束与失败条件 |
| --- | --- | --- |
| 5 秒识别 | 入场页以真实附近房间为主，明确“创建房间”和“手动加入”；显示“每人运行自己的程序”，不提前展示空成员卡。搜索中、无房间和发现不可用分别说明下一步。 | 搜索刷新保留正在操作的列表项和焦点；真实空列表不装填假房。若新人无法解释“我看到的是房间而不是在线朋友”，则首屏失败。 |
| 首次成功 | 点加入后该行原位显示“正在加入”，失败显示原因及重试/手动入口；真实 room.joined 后才进入共享面，提示“已进入房间，麦克风由你开启”。 | 不模拟系统授权；各自本机 EXE 和浏览器工作。保留创建/返回选择；结果来自信令，不能提前声称语音连接成功。 |
| 同伴共处 | 姓名边按真实成员数出现；安静时也知道谁在场、自己麦克风状态及谁是房主。声音入口可展开各真实来源，注明音量只影响本机。 | 无实时说话/是否听见/情绪信号就不显示；空位不冒充人。DOM 采用有名称的成员列表，顺序稳定，原生 button 和可读的状态文字。 |
| 共享接力 | A 停止后显示“共享已结束，语音继续”；下一人的“分享我的屏幕”变为可用，B 自己点击系统选屏。收到 B 的真实状态后 B 成为画面来源边，其他人的在场与麦克风控制留在原区域。 | 不实现假队列、自动交棒或替对方选屏；浏览器 getDisplayMedia 跟随用户手势。系统声音隔离未确认时仍发送已捕获音轨；缺轨按真实选择分支。保留同一个实际 video 节点，不重建、不复制流、不额外重协商，图像 contain；用户主动只语音不被房间更新强制改回观看，本机分享者选择只语音时停止自己的共享。 |
| 失败恢复 | 选屏取消回到空闲共享面并保留语音；连接中断明确区分房间、声音和画面，不把静止旧帧称为直播；房主结束与本机离开分别解释后果，提供真实可行下一步。 | 页面状态来自现有事件与权限；失败不能伪装成已连接或已结束。状态文本以适当 live region 公告，避免每次统计刷新反复打断。任何视觉过渡都不能阻止取消或重试。 |

窄窗将成员边压成位于画面上方的简洁列表，DOM 顺序仍为房间标题、成员、内容、控制，不用视觉重排让键盘顺序跳跃；全屏时停止/静音可发现，焦点不可被浮层遮挡。使用系统字体并检查长中文房名、200% 缩放与对比度；动画只在状态改变时短暂连接来源标记，`prefers-reduced-motion` 下直接切换并保留同样的文字和功能。主题是后续变量，先在同一色系比较结构。

## 用同样任务证明或推翻

对基线、来源展开、票和声音台使用相同成员、房间名、窗口、真实状态与视频素材，顺序轮换；让未看过原型的人完成“找到房间并加入、判断谁在、A→B 接力、取消选屏、只聊语音后恢复、断线判断和离开”。记录首次找到主动作时间、需要提示次数、错误判断、遮挡与文字溢出，以及结束后记得的变化；不以 81 种组合、DOM 测试通过数或单张精修图作为用户满意证据。

硬约束：任何状态不得假成功；语音、视频、系统声音和房间连接分别真实；停止屏幕不误停语音；权限只由浏览器请求；键盘/触摸/减少动态可操作；观看保持画面完整并保护实际 video 流。原型只证明理解和交互，真实屏幕、三机、系统声音隔离和背景性能另做实机验收。
