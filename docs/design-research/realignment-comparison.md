# 两轮设计方向对照与交叉评审

用户要求两轮子智能体中有价值的方向都继续发展。统一实验室因此保留第一轮三个空间结构和第二轮三个研究方向，允许在同一模拟情境、同一外观下比较，也允许按入场、语音和观看阶段组合。视觉主题独立于结构。

| 方向 | 保留的核心体验 | 本轮真实浏览器观察 | 尚待判断 |
| --- | --- | --- | --- |
| 房间会展开 | 房卡与房内沿用名称、三席占用、色边和共享状态，进入与返回对应房间。 | 本地浏览器确认加入后的身份与焦点、返回后的房卡焦点；普通动态偏好下运行原生过渡。 | 跨浏览器动画回退的观感，以及这种连续性是否足够明显。 |
| 三人一桌 | 两位同伴、中央活动和近端本机形成空间关系；音量和麦克风在各自旁边。 | 1440px 可在成员旁调整语音并打开其声音面板；390px 为保留阅读顺序改为纵向。 | 窄屏时围坐感与内容高度的取舍。 |
| 只留画面 | 观看以画面为主，房间和音频操作留在边缘；停播后继续语音并自主选择共享。 | 看到了完整画幅和常用控制；模拟停播后进入有分享入口的语音状态。 | 不同画面亮度、实际播放和更小短窗下的表现。 |
| 同伴通道 | 从成员进入对应语音；分享者还关联共享声音。 | 在共享情境可从分享者打开独立声源。 | 首次使用者能否发现成员入口。 |
| 来源展开 | 分享者与共享画面相连，其他人留在侧边。 | 画面与分享者同处一个来源区域。 | 对窄屏和纯语音的舒适度。 |
| 接力现场 | 当前活动结束后，原处给出自愿开始分享的入口。 | 模拟朋友停播后可见下一步，无队列或自动接管。 | 是否比其他结构更容易理解。 |

三位子智能体分别交叉检查了旧结构。根据检查修正：区分成员语音未到达与连接中断；让围桌的视觉顺序与 DOM 顺序一致；在真正停播后的语音状态就近提供分享；人数达到三人时禁用加入；让画面优先的断线说明进入正常布局；为加入中、进入和返回补充焦点；修复房间展开观看页在桌面高度内挤走麦克风的问题。

浏览器证据与自动检查范围见 [验收记录](../../demos/experience-lab/QA.md)。桌面截图说明结构有可观察差异，并不等于用户已认可设计；新一轮的三个结构仍有相似的基础组件，应通过实际体验决定是否合并或继续拉开差异。正式前端和 GitHub 发布都等待满意的方向。
