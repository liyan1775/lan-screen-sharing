# 同伴通道 · 实现说明与自评

## 值得体验的闭环

在“朋友正在共享”场景，观看画面上方的分享者就是可操作的同伴入口：选择该人，由公共 `member` 浮层显示属于此人的语音及实际可用的共享声音；两种音量分别调节，只影响本机。选择“只聊语音”后，房间与成员入口仍在，页面说明画面和共享声音已在本机暂停；恢复观看重新回到当前模拟分享者。系统声音不可用、断线、停止共享或成员变化都应由根状态与公共 helper 给出真实演示状态，不由布局臆造。

同伴入口是观看时分享者与语音时成员的同一动作（`member` + 成员 ID），并非两个独立的声源模型。主播画面下说明“只聊语音会停止你的共享，麦克风状态不变”；不能把观众本机暂停的含义套到主播身上。朋友停播后，空闲状态出现共享按钮；模拟选屏取消由根入口负责，需核对麦克风与房间不变。

## 结构与契约

- `layouts/channel.js` 只注册 `D.layouts.portal` 的三个阶段，不安装事件、定时器或设备访问。所有动作由根入口的 `h.button`、`h.person`、`h.people`、`h.controls`、`h.shareButton` 和 `h.screen` 提供。声音浮层由根入口使用 `h.personAudio` 负责；布局不同时渲染第二套音量模型。
- 入场为可操作的房间列表和创建/手动加入；满房禁用，空房、查找、受阻分别有解释，任何房间名均经过转义。
- 语音阶段通过成员对象进入个人控制；共享状态集中在一处，空闲时可以开始共享。观看阶段把真正演示画面放在可压缩的剩余区域，分享者入口在画面旁且主控制不在图片下方长距离滚动；无共享或断线由 `h.screen` 渲染明确空态。
- 样式使用公共主题 token，结构不按外观切换；支持窄窗换行、焦点可见和减少动态。演示图片与状态均为模拟，不证明真实媒体或本机播放。

## 自批与待验收

1. 人与声源关系依赖公共 `h.person` 的可见名称、`member` 浮层锚定和 `h.personAudio` 正确过滤真实模拟来源；若浮层过远或看起来与成员无关，本方案的核心价值会消失。根入口应验证无系统声音时没有假滑杆，本机不提供远端自我音量，音轨与静音状态保持一致。
2. 同一对象在语音与观看阶段出现，并不自动等于用户理解关系。需对照其他方案观察首次操作：能否从分享者名字调低游戏声而不调低他的语音，切只语音后能否独立找回观看。
3. `h.controls` 是共享的通用控件集合，虽使权限语义一致，也有工具栏味道。应实测窄窗下按钮密度、文本换行、完整画面和控制是否同时可见；若拥挤，优先优化公共控件，而不是隐藏停止或麦克风。
4. 观看阶段出现成员入口和分享者入口时，要观察是否有重复感；当前只在“房间里”列出其他成员，避免把分享者重复陈列。成员消失、重连、浮层打开时阶段切换、Escape/Tab 与焦点归还需要根入口验证。
5. 截止本次交付仅做 JS 语法及静态结构检查，未独立启动浏览器、真实媒体或设备；根代理整合后需对 1440、900、390 宽度和三种外观做实际截图、键盘和交互验收。模拟音量延续不等于生产端轨道重建后偏好一定保留。
