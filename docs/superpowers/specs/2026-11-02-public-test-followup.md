# 0.2.1：实机反馈后的修正与定位

用户报告 0.2.0 在一般场景约 59 FPS、其余大部分功能正常；同网房间未自动出现，但手动加入正常。Edge 在 Windows 10 和 Windows 11 都出现系统声音隔离失败。后续补充：第一人称全屏游戏只有准星，观众画面中心却多出系统鼠标；游戏全屏时接收降为 20–30 FPS，分享者一切回网页便恢复 59，因此不能靠切换窗口现场读数。

本轮保持整屏、三人以内、单人轮流共享、独立语音、轻量单 EXE 及本机浏览器界面。先修补既有采集和发现路径，不擅自安装驱动、修改网络权限或添加原生音频采集器。

- 发现：每次查询同时走选定私网子网的广播与 TTL=1 组播，共用随机查询 ID；回复仍仅单播到实际查询源，并受原有成员邀请/来源/限速/缓存规则限制。组播初始化失败时尝试仅广播。忽略单个过长 UDP 包；其他致命收包错误释放套接字并明确暴露失败，启动错误不再静默隐藏。折叠诊断显示网卡、收发计数和固定错误类别，不包含房间码或控制凭证。
- 声音：区分浏览器认识约束、当前音轨允许约束、最终设置三层。初始未启用时在能力允许或未报告的情况下显式 applyConstraints，并重读设置；只有最终明确 true 才进入原有人工听感流程。失败则停止系统音轨、保留未发送的整屏画面，提供明确的无游戏声音继续按钮。检查期间离房立即停止采集，迟到结果不能恢复共享。兼容性诊断包含浏览器版本和固定状态，不含原始错误文本。
- 鼠标：默认请求 cursor=never，允许成员选择共享主播鼠标；采集和画质变化均携带该设置。浏览器可以忽略此请求，因此不宣称已经抹除嵌入视频的指针。观看区自己的指针和全屏控件空闲后隐藏，移动/键盘聚焦恢复。
- 帧率：视频发送设置 maintain-framerate，浏览器拒绝时仍应用基本 FPS/码率。实际采集支持 media-source 帧数差；接收、发送、采集和设置值区分。保留最多 120 次仅含允许字段的统计历史，包含页面前后台状态、原生瞬时 FPS 和帧数差区间平均；切回网页后不会用已恢复的 59 FPS 覆盖历史。页面隐藏/恢复时额外取样，单次采样互斥。原生指标缺失时如实记为未报告。

验收：纯内存传输测试模拟丢弃全部组播而仅广播完成发现，检查子网边界、重复回复限流、过长包后仍能收包和错误可见；Node 检查声音成功恢复/无效约束不能放行、未确认前不共享、检查中离房、鼠标空闲控制、帧率优先回退、历史和生产页面复制事件。编译新 Windows 包，原 0.2.0 包保留。

本轮没有启动服务、浏览器或真实屏幕/麦克风采集。先前测试服务启动遭自动审批拒绝的边界保持不变，不用其他启动路径绕过。跨设备广播、Edge 声音、真实游戏捕获/鼠标和长时间表现仍需实机日志；本轮不能据纯测试宣称这四个实机问题全部解决。
