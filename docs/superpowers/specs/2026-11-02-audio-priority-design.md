# 0.2.2：系统声音优先与后台帧率排查

用户本轮明确修订优先级：主播能共享系统声音高于声音隔离，隔离能力未知不能阻止共享。用户进一步确认低帧率跟随浏览器后台状态，回到前台便恢复，不限于游戏独占全屏。

采用现有浏览器采集与 WebRTC 路线，不换采集器或增加原生依赖。系统声音选择仍由主播和浏览器授权；请求尽力隔离，拿到声音就发送，隔离为 false/未知/接口不支持均显示状态与可能回声提示，不再自动停轨、要求通过人工检查或强制改无声模式。人工听感检查只记录结果；不通过也不自动关闭声音，用户可自行停止系统声音。没有捕获到声音时仍明确告知并保留继续无声画面的选择。默认模式沿用无游戏声音，选择组合模式后可以正常直接开播。

考虑过继续强制隔离、加额外“承担风险”确认、移到原生音频采集器：前两项不符合本轮明确要求，后一项超出轻量修补范围。此次不新增任何确认拦截；用户本轮说明直接授权该行为变更，不再为相同取舍反复征询。

后台帧率已经检查现有发送链路：浏览器采集轨直接 replaceTrack 至 WebRTC，没有 canvas/rAF/JS 定时器视频生成，没有页面隐藏时的主动降帧逻辑。Edge 官方说明节能策略可降低视频流畅度，提供单站点保持活动例外。它是有依据的待验证假设，不是本机确诊；先做只改变 Edge 节能模式的一变量前后台实验。页面与中文说明加入具体设置步骤、复制当前 localhost 地址、切回前台后历史记录查看；保留现有原生采集/发送/接收统计，不用忙循环、无声播放、伪造前台或全局浏览器启动参数绕过。

交付 0.2.2 包与更新说明，保留旧包。代码与纯测试可完成；历史自动审批拒绝启动服务的边界不变，不启动产品、测试服务、浏览器或真实采集来绕过。不能宣称后台低帧率已经修好，除非得到相应实机结果。
