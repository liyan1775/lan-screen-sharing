# 公测改进：房间发现、全屏、成员轮流分享、帧率

用户反馈：观看缺全屏；创建/加入身份将开播权限锁死，希望任何人可以开播，也能纯语音；60 FPS 档实看似只有 30 FPS。

沿用最多三人、局域网、本机浏览器和单 EXE、整屏采集及声音隔离规则。用户已明确确认“同一时间一人开播，房间内随时换人”，按此实现任意成员轮流分享。

- 全屏：画面区域按钮和双击切换，Esc 跟随浏览器退出；视频保持比例，停止画面时退出全屏，语音不受影响。
- 房间创建者与当前分享者分离。创建者仅负责房间存续/结束；所有已加入成员都可申请空闲的分享席位，停止即释放；有人正在分享时明确提示等待。无人分享时三方语音保持。服务器按认证身份原子分配分享权，不接受客户端伪造分享者或结束他人房间。
- 媒体三对连接预协商 video/systemAudio/microphone，屏幕槽为双向，音频仍分轨。更换分享者仅更换屏幕轨，保留语音；当前分享者由房间状态选取，不能拿任何收到的视频冒充当前分享者。
- 60 FPS：屏幕采集明确请求所选 frameRate，切换质量同时 applyConstraints 及更新 sender；getSettings 设置值与实际 media-source/outbound/inbound 统计分别显示，缺失帧率用原生帧数差计算。浏览器报告带宽/CPU 限制则如实显示；不保证设备一定可达 60 FPS。
- 旧公开测试包保留，新包标注 0.2.0，要求所有参与者升级同版，更新非程序员说明。只编译和允许的纯测试，不绕过此前服务启动拒绝。

验证：新增全屏、采集设置更新和帧率统计检查；分享席位并发/权限/离房回收的 Go 纯内存检查；三方动态媒体与房间状态的 Node 检查；编译当前 Windows 候选，保留实际三机表现未验证的边界。

## 同轮补充：附近房间一键加入

用户进一步要求打开后直接看到房间列表并加入。首页默认展示同一选定私网 IPv4 子网的公开房间（名字、人数、是否在共享），点“加入房间”自动沿用原受限信令桥加入，地址、端口和房间码不再需要手填。创建者可填写房间名；默认勾选“允许同一局域网发现并直接加入”，可取消，取消后不广告该房间。手动邀请作为备用收进折叠信息和“手动加入”。这是用户要求的可发现/直接加入语义，公开房间允许同网成员获得观众加入能力，主机/本机控制凭证始终不公布。

本地服务使用 UDP 组播查询（239.255.77.77:49877），只在选定网络接口发出、TTL=1；房主只向实际查询源的 UDP 地址单播有限房间响应，不接受任意回复目标。响应需回显最近查询随机 ID；来源必须是选定私网子网，消息大小/条数/缓存受限，房间约 7 秒未刷新移除。查询不广播加入码；观众加入码在单播回复和本机凭证保护的列表 API 内使用，不放到房间卡片文本或 URL。私有房间、控制凭证不进入发现数据。

服务创建、退出和页面关闭生命周期包含发现套接字；未找到私网/无法组播时，不影响手动加入。页面每三秒读取本机缓存，防止并行请求重复；满房/自己创建的房间不可重复加入。Windows 组播支持与实际跨设备发现仍需运行验证，不把纯缓存/HTTP/DOM 检查当作真实发现成功。
