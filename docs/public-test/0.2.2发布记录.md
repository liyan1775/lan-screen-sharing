# 0.2.2 系统声音优先测试构建

日期：2026-11-02（Asia/Shanghai）。用户本轮明确：主播共享声音的优先级高于隔离；不能因无法确认隔离而禁止共享。另确认低帧率与浏览器前后台状态相关，后台降至 20–30 FPS，回到前台恢复，不能仅归因于独占全屏游戏。

## 行为修订

- 选择含系统声音的模式后可直接开播。浏览器已捕获的系统音轨在隔离 API 不支持、设置为 false 或未报告时仍发送；不再用人工确认拦截普通开播，也不再追加可能失败或等待的 exact 隔离约束。首次采集仍尽力请求隔离。
- 隔离与听感状态仅作信息。“检查是否回声（可选）”只更新结果，选“听到了回声”仍继续发送。分享者主动点“停止共享系统声音”才停这一路，保留视频与麦克风；即使发送者解绑失败也停止旧音轨并发布最新状态。
- 没有捕获到有效系统音轨时仍明确告知，允许继续已有画面或取消重选；已经结束的音轨不当作成功有声共享。原有离房、迟到采集及共享席位规则保留。
- 默认仍为画面与语音、无游戏声音，避免替使用者改变选择；需要游戏声时主动选组合模式即可。两人也能直接使用，不要求先凑齐三人验收。

本轮修订覆盖旧设计和 0.2.1“隔离未确认就停止声音”的规则。历史记录保留原貌，不当作本版当前要求。

## 后台帧率调查

发送代码直接把 getDisplayMedia 音视频轨交给 WebRTC，不依赖 JS 定时器/canvas/rAF 逐帧产生视频，也没有页面隐藏就改帧率目标的逻辑；visibilitychange 目前只额外取统计。没有通过虚假音频、忙循环或全局浏览器参数强保前台。

Edge 官方说明节能模式可能影响视频流畅度，且支持“始终保持这些站点处于活动状态”例外；正在捕获屏幕的页面通常不应进入睡眠，因此不能把“睡眠标签页”“节能模式”“Windows 进程效率策略”混为一谈。[Microsoft 官方性能说明](https://support.microsoft.com/en-us/edge/learn-about-performance-features-in-microsoft-edge)

用户暂时不方便做节能模式对照，但补充：Edge 仍在后台，Steam 商店页播放视频能让接收升至 55–60 FPS。它排除了“所有后台状态均锁 30”的说法；因为画面内容及系统负载同时改变，还不能单凭它区分桌面更新/合成、采集路径与电源调度。Chrome 的原生桌面采集也有自己的帧调度和负载控制，不受本项目 JS 逐帧驱动。[Chromium 采集实现](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/content/browser/media/capture/desktop_capture_device.cc)

浏览器/系统后台性能策略仍是待验证假设之一，不能宣称确诊或修复。界面和说明提供设置位置与复制本页地址按钮，复制时剔除查询和片段；启动端口改变后可能需重新添加站点例外。保留前后台统计历史用于后续定位，没有额外播放视频维持帧率，也没有自动改变浏览器、操作系统或网络设置。
