# 0.2.1 修正与定位测试构建

日期：2026-11-02（Asia/Shanghai）。生产源码提交 `4509d4d`，基于上轮 0.2.0。所有参加的人使用同一个新包，先退出旧程序。

用户实机反馈：一般场景约 59 FPS，第一人称游戏全屏后接收降至 20–30，分享者切回网页又恢复 59；游戏只有准星，却在观众画面中心出现系统鼠标。房间自动发现失败但手动加入正常。Edge 的 Windows 10 与 Windows 11 都出现系统声音隔离失败，完整浏览器版本尚未提供。不能把这些现象直接归因于网络或 Win10，也不能把普通场景的 59 FPS 当成全屏游戏已验收。

## 改动

| 反馈 | 本轮更改 |
| --- | --- |
| 找不到房间 | 同一次查询同时发组播和选定私网子网广播；组播初始化失败时尝试广播。仍使用最近随机查询 ID、实际来源地址、原有限速和邀请规则。单个超长 UDP 包不再使 Windows 收包循环永久退出，启动/致命收包错误不再伪装成健康空列表。增加可复制的网卡、收发计数和固定错误类别。 |
| 系统声音隔离失败 | 区分接口识别、音轨能力和最终设置。初始未启用时，能力允许或未报告则显式应用 exact 约束，再核对设置。最终未确认 true 就停止系统音轨；保留未共享的整屏画面，让用户明确点击继续画面与语音。诊断记录初始/最终值、能力、约束结果和浏览器版本。检查过程中离房会立即停轨，迟到结果不能恢复共享。 |
| 游戏中心残留鼠标 | 默认请求 cursor=never，并提供“共享我的鼠标”开关；浏览器可能忽略，实际报告进入诊断。观看区自己的指针/全屏控件空闲后隐藏，移动和键盘聚焦恢复。该 CSS 效果不能抹掉已经嵌入视频的指针。 |
| 游戏全屏时只有 20–30 FPS | 发送策略请求 maintain-framerate，拒绝时仍应用基本码率/FPS。补充实际采集帧数差、编码格式和累计平均编码时间；保留最多 120 次仅含允许字段的前后台统计，包含原生瞬时值和区间平均。页面隐藏/恢复时额外取样，回到网页后复制诊断仍含此前数据。 |

统计仅存在内存中，不录屏或记录声音。后台采样可能被浏览器延后，区间平均会保留实际跨度；无法补出缺失的瞬时值，指标缺失仍写“未报告”。不扫描局域网端口、不改变防火墙、不安装驱动或系统服务、不新增原生媒体采集器。

## 验证

- Node 纯检查：`node --test tests/js/*.test.js tests/e2e/fixtures/synthetic-media.test.js tests/e2e/visible-harness/assertions.test.js tests/e2e/visible-harness/diagnostics.test.js tests/e2e/visible-harness/silent-output.test.js`，**123/123 通过**。最后的页面取样入口微调后，生产 app、历史与质量相关的 8 项检查再次通过。这些断言检查不等于浏览器 E2E 已运行。
- Go `test ./internal/discovery ./internal/room ./internal/protocol -count=1` 通过；发现传输测试使用内存套接字，模拟丢弃全部组播而仅广播完成查询、回复、缓存及一键加入信息生成，没有创建真实网络套接字。
- Go `test ./internal/app -run '^TestRoomDiscovery' -count=1` 通过，使用内存 HTTP；包括同源与控制凭证、私有房间过滤、控制凭证不泄露，以及启动失败可见。
- Go `test ./internal/signal -run '^TestMemberPresentationUsesAuthenticatedSessionAndPreservesState$' -count=1` 通过，仅使用内存连接；`test -c ... ./internal/app` 编译通过，未执行该测试程序。
- 产品构建退出码 0。ZIP 六个固定 UTF-8 路径、逐文件 CRC、候选/dist/包内程序 SHA 一致、AMD64 GUI 结构、说明与源文件内容一致、UTF-8 BOM/CRLF、HTML 标签/链接及页面按钮 ID 静态检查通过；完成独立解包。旧两版 ZIP 和回退程序已核对。
- 本轮没有启动服务、浏览器或真实屏幕/麦克风采集，未执行需要服务的整套 verify；此前服务启动被自动审批拒绝的边界保持不变，没有换启动方式绕过。

## 剩余实机验证

跨设备广播、Edge 的实际声音隔离、游戏全屏帧率、隐藏采集指针、页面实际渲染和三方长时间运行均未在本版实测，**不能宣称上述问题全部修好**。尤其帧率优先策略不能保证底层屏幕采集本身达到 60，浏览器忽略 cursor 请求时也不能据此宣称异常指针已消失。原 0.1.4 固定角色的可见测试 runner 不适用于本版新流程，不把其结果沿用为本版通过。

下轮最小证据：双方复制查找诊断；分享者在出现问题的全屏游戏中持续约半分钟，再返回页面复制媒体诊断。声音仍失败时，这份诊断同时含本次音轨能力与隔离结果。无需让分享者在全屏游戏中切回来读实时 FPS，也不要求现在重新安排三台电脑才能收集这些数据。

技术依据：[W3C 屏幕采集约束](https://www.w3.org/TR/screen-capture/)、[Chromium 对接口识别与系统支持的区分](https://chromium.googlesource.com/chromium/src/+/4a2089e32947bb1ef25b956634ef1d8bbcaeb7f6%5E%21/)、[W3C 帧率与分辨率降级偏好](https://w3c.github.io/mst-content-hint/)、[Microsoft UDP 收包错误说明](https://learn.microsoft.com/en-us/windows/win32/api/winsock/nf-winsock-recvfrom)。这些资料说明 API/系统的边界，不能替代用户本机的实际音轨和游戏数据。
