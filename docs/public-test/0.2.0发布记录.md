# 0.2.0 公测改进构建

日期：2026-11-02（Asia/Shanghai）。用户确认同一时间一人开播、成员可在房间内随时换人；原三人规模不变。

## 实现

生产源码提交 `2099b4b`（包含 `6fef6d2` 的媒体改进和 `e87b9d4` 的待授权采集清理修正）。同轮补充实现首页房间列表及一键加入。

- 画面区域增加全屏按钮、双击切换和 Esc 状态同步，保持画面比例，停止画面后退出全屏；失败会显示提示。
- 房主与当前分享者分离。服务端按认证会话原子分配单一分享席位，禁止另一成员抢占、释放或伪造当前分享者；停播/离房/断线席位过期后回收。短暂信令恢复窗口保留当前媒体。房主仍维护房间，退出时结束整个房间。
- 三对媒体连接均预协商独立屏幕视频、系统声音和麦克风槽位，成员轮流分享时替换轨道，保留麦克风与连接。当前观看对象来自服务端 presenterPeerId，非当前分享者的系统声音保持静音。状态带递增序号，避免旧状态回包将新分享者覆盖。
- “只聊语音 / 恢复观看”改变本机的画面和系统声音，保留成员语音及用户静音偏好；分享者自己切到纯语音时先停止自己的共享。不承诺节约接收带宽。
- 屏幕采集开始时请求所选宽高与 frameRate；切换档位会 applyConstraints，再更新每条视频发送者的编码参数。内容提示为 motion。程序不再只设置 maxFramerate 而遗漏采集请求。
- 设置值、实际采集、每条连接的实际发送/接收统计分开；原生统计未提供 FPS 时以帧计数差计算，原生带宽或 CPU 限制单独显示。不会把目标 60 或 getSettings 的 60 当成实际已达 60。
- 首页首先显示附近房间，包含名字、人数和共享状态；一键加入自动携带原有普通成员邀请，免填 IPv4、端口和房间码。列表每三秒更新，满房/本机房间不可重复加入，失联缓存约七秒过期。加入失败返回列表，创建/手动加入界面可返回列表。
- 创建房间可命名，默认允许同网发现并直接加入，也可在创建前取消。私有、已结束、已过期房间不广告；手动加入保留为备用。发现仅通过选定私网子网的 UDP 组播查询和单播回复，TTL=1，响应必须回显最近随机查询 ID，来源/字段/数据大小/缓存/响应频率受限。始终不传播本机和房主控制凭证。

## 复测重点

三个人都使用本包：A 创建房间，B/C 首页是否自动出现房间、点一下是否能加入；房间结束后是否从列表消失，取消公开发现是否不显示，手动备用是否可用。保持三方麦克风；A 开播→停止→B 开播→停止→C 开播，确认语音始终保留。观看时测全屏按钮/双击/Esc，再测只聊语音/恢复观看。选择 720p60、1080p60，在持续运动游戏中比较采集设置、实际采集和双方发送/接收统计；若仍约 30 FPS，记录限制提示及游戏/系统/浏览器版本，按反馈表回传。

技术参考：浏览器采集约束与发送编码上限分别作用在不同阶段，参见 [getDisplayMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia)、[applyConstraints](https://developer.mozilla.org/en-US/docs/Web/API/MediaStreamTrack/applyConstraints)、[RTCRtpSender.setParameters](https://developer.mozilla.org/en-US/docs/Web/API/RTCRtpSender/setParameters)。全屏使用标准 [requestFullscreen](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen)，由用户点击触发。
