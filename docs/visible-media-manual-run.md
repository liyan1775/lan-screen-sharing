# Visible media fixture: manual startup

After reviewing `scripts/start-visible-media.ps1`, run it manually from Windows PowerShell 5.1 or later in the repository when the fixture services are needed. It launches only the fixed, hash-pinned Go test binary in four hidden test processes (one host instance and three viewer instances); it does not start a browser, open the URLs, request device access, or capture real media. Open the printed localhost URLs in the authorized CUA session. The CUA checks cover eight synthetic-media scenarios plus ordinary seat reuse across these four instances. The current runner is `.superpowers/sdd/lan-screen-sharing/build/visible-media-harness-0.1.4-3fbc2ab-e24fa89.test.exe` (13,128,704 bytes; SHA-256 `66477C3E444271BEB15C3247F82F023E82D384B1FDDF8FADE60BEF8487DF6951`), matching the starter. Product assets include the `3fbc2ab` microphone control fix. See the [build record](../.superpowers/sdd/lan-screen-sharing/release-0.1.4-preparation.md) for exact binary inputs.

The test-only JavaScript assets are served from the current repository checkout at runtime, not embedded in the `.test.exe`: `serveVisibleHarnessAsset` reads them from the process working directory, and the starter sets that directory to the repository root. The assets are `tests/e2e/visible-harness/controller.js`, `assertions.js`, `silent-output.js`, and `tests/e2e/fixtures/synthetic-media.js`. The latest native retest used these files through `3265296`, including `a39ecfc` (stop only explicitly cloned measurement tracks) and `3265296` (measure cessation in a separate post-stop window, with fresh voice PCM). Use that source snapshot to reproduce the recorded run. The executable hash alone does not pin these JavaScript files.

The fixture waits up to 45 minutes for its pages. The product default startup grace remains 30 seconds, and the product's last-page shutdown behavior remains active. During its bounded READY wait, the script tolerates temporary inability to read process identity, but accepts a READY only after the process identity is verified again. It prints each role, alias, owned PID, and verified localhost URL after that process reports READY. It never prints or persists the shared owner token or any local/host/resume credential. On Ctrl+C or startup failure it requests each still-running, identity-matched fixture's same-origin shutdown using that fixture's in-memory local nonce; if READY or nonce validation is unavailable, it reports the owned PID for human handling and does not terminate an unverified process.

The latest [native CUA retest](../.superpowers/sdd/lan-screen-sharing/visible-media-0.1.4-retest-report.md) records passing checks for three-party track/MID/sink correlation, received PCM signatures, per-pair RTP, viewer voice, full-room and role refusal, microphone denial, ordinary rejoin, automatic bridge recovery, actual frame statistics, and post-stop voice. The cases were executed in documented phases with page reloads after test-harness fixes; this is not one uninterrupted all-green automated suite. The first viewer's initial stop window failed and a later repeat passed, so no immediate-stop latency bound is established. The run also verified refresh, multiple project tabs, last-tab exit, and all four processes exiting. Background/frozen-tab behavior remains unverified.

These are same-machine synthetic results. Real monitor selection and game switching, physical microphones and listening, three-device LAN interoperability, a ten-minute game session, system-audio voice isolation, and performance still require the approved real-device acceptance. The separate Playwright command `node --test tests/e2e/mesh.spec.js` has not been executed; do not infer that command passed from the native CUA results.
