# v0.5.0 · 单次编码与性能优化公开测试版

两位朋友观看同一画面时，分享端现在只编码一次。原有 1080p60 / 8 Mbps 默认目标、系统声音、三人语音和房间文字继续保留，不通过降低画质换取性能。

下载 [Windows x64 完整测试包](https://github.com/liyan1775/lan-screen-sharing/releases/download/v0.5.0/lan-screen-sharing-0.5.0-windows-x64.zip)，完整解压后打开“先看这里.html”。也可先浏览[产品介绍](https://liyan1775.github.io/lan-screen-sharing/)。

## 本版改动

- 视频和系统声音只编码一次，分享者本机程序把相同编码的 RTP 负载分别发给最多两位观众，不解码或再次压缩。麦克风与房间文字继续使用浏览器直连。
- 切回游戏、窗口失焦或页面隐藏时，默认暂停自己的预览播放；采集、发送及观众播放继续。回到页面恢复同一条流，可在设置关闭此选项。
- 语音模式不查询视频统计；共享时诊断收起采用低频采样，展开后及时更新。隐藏的房间列表与诊断区域停止无用刷新，重复的采集/编码配置不再反复应用。
- 新的本机媒体连接先完成带宽反馈，再挂入视频轨道，避免浏览器按较低的初始估计缩小画面。没有游戏模式画质上限，也没有自动切换未通过帧率验证的编码器。
- 本机媒体会话按页面隔离，另一个页面开始共享或旧会话的迟到停止不能关闭当前页面的媒体连接。退出和停止时及时释放资源，保留语音。
- 新增 Apple 风格产品介绍页，提供真实界面切换、编码方式对比、使用说明和下载入口。

## 验证与范围

Go 全包、164 项 Node 行为测试、11 项三人原生 WebRTC / 合成媒体测试通过。严格用例同时开启三人的合成麦克风，核对唯一视频编码器和两位观众的实际尺寸为 1920×1080，实际编解码帧率至少 57 FPS，目标仍为 60 FPS / 8 Mbps。完整界面检查覆盖 30 张截图、21 个状态的 axe 检查及 17 个嵌入资源哈希。

性能对照同时计入分享端浏览器和本机 Go 程序的 CPU 时间，观众在独立浏览器进程。保留所有通过及失败窗口：旧双编码版在部分窗口会缩小画面，这些窗口不计入“同画质 CPU 降幅”。完整数据、构建哈希及测量口径见[性能记录](../performance/2026-11-06-single-encode.md)。

用户确认本轮可以不使用真实游戏验收，因此不要求提供游戏帧时间 CSV。以上是同机合成媒体验证，不表示真实游戏 1% low / 0.1% low 已经实测，也不承诺任意设备都达到相同帧率。真实三设备、物理屏幕与麦克风、声音隔离听感仍需实际设备反馈。EXE 未数字签名。

## 升级

**所有成员必须统一升级至 0.5.0。** 本版使用新的画面共享协商，0.4.x 与本版不兼容。退出旧程序，运行新程序后重新创建房间。房间默认无固定时长上限、30 秒恢复保留期、停止屏幕共享继续语音的行为沿用。

构建仍为 Windows x64 单 EXE，旁边和完整包中提供 Pion、WebSocket、Go、图标及传输依赖的许可原文。发行附件包括 EXE、完整 ZIP、许可和 SHA256SUMS；校验值以本发布附带的文件为准。
