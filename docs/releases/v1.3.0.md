# v1.3.0 正式版 · LAN / 分享

这个次版本重点提升高动态 3D/FPS 游戏场景下的 1080p60 画质上限与编码效率，消除诊断文案歧义，并补齐游戏全屏后台期间的码率与编码档位滚动历史，让排查画质或帧率波动一次到位。

## 新功能与改进

1. **1080p60 默认码率上限提升至 25 Mbps（界面零新增选项）。** 保持简洁的三档画质选择（`1080p · 60 FPS`、`720p · 60 FPS`、`720p · 30 FPS`），将默认 `1080p60` 发送码率上限从 15 Mbps 提高到 25 Mbps；本机单次编码中继的本地带宽预算同步抬高至 36 Mbps，为高动态画面、音频和突发关键帧留足余量。`720p60`（8 Mbps）与 `720p30`（2.5 Mbps）保持不变。
2. **H.264 优先协商 High 档位，并支持平滑回退与自动恢复。** 屏幕共享优先选择支持 1080p60 的 H.264 High > Main > Constrained Baseline 档位，提高同码率下的高速运动细节保留。当房间内有仅支持 Constrained Baseline 或仅支持 VP8 的观看端加入时，自动降级兼容以确保所有成员持续出画；对方离开后自动尝试恢复 High 档位，无需重新选取共享屏幕。
3. **硬件编码文案更准确，补充采集帧率建议。** 取消容易被误读为降频省电的「节能编码 / 节能解码」表述，按浏览器上报准确区分「硬件编码 / 硬件解码」与「软件或未加速编码 / 解码」。采集帧率偏低时的诊断提示新增「适当限制游戏帧率，给显卡留出余量」建议，与独占全屏/无边框窗口对比并列。
4. **全屏后台期间的媒体诊断历史补齐码率曲线与切换边界标记。** 即使关闭设置面板全屏玩游戏，后台滚动历史（最多保留 120 条）也会持续记录本机当地时间、实际发送码率、编码目标码率、本机转发可用带宽估计、活动 H.264 档位（Profile / Level）、采集与发送区间均值、区间 QP、区间与累计编码耗时、各原因限流时长、RTT 及重传 / NACK / PLI / FIR / 关键帧增量。前后台切换瞬间单独标注为 `前台→后台（跨切换区间）` 与 `后台→前台（跨切换区间）`，避免把切窗瞬间误判为游戏内真实表现。

## 下载与升级

建议房间内所有成员统一使用 `v1.3.0`。完整解压 Windows x64 ZIP，先查看包内的 `先看这里.html`，再双击 `局域网屏幕共享.exe`。 [下载 Windows x64 ZIP](https://github.com/liyan1775/lan-screen-sharing/releases/download/v1.3.0/lan-screen-sharing-1.3.0-windows-x64.zip) · [发行附件与 SHA-256](https://github.com/liyan1775/lan-screen-sharing/releases/tag/v1.3.0) · [产品介绍](https://liyan1775.github.io/lan-screen-sharing/)

## 验证范围

本机回归使用 Windows x64 成品、Edge、合成媒体与真实 WebRTC，覆盖界面、三人连接、25 Mbps 发送上限与 36 Mbps 本机转发预算、H.264 High 与 Baseline / VP8 兼容回退及恢复、关设置后台历史剪贴板读回、刷新恢复、性能及宣传页。回归核对 1080p 分辨率、帧率统计和编码参数，60 FPS 与 25 Mbps 是画质目标，真实显卡与游戏（如 CS2）满载下的实际采集帧率与动态观感仍受设备负载、驱动与局域网条件影响。
